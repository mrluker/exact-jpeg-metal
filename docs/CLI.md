# Command-line tool and scripts

The `ejm` tool and the scripts are developer tools for testing, benchmarking and maintaining the library. They
are not needed to use it; the library API is in [API.md](API.md). `ejm` is its own package, `Tools/Package.swift`
(sources in `Tools/Sources/`), which depends on the library package by path; the library package itself
(`Package.swift`) has no reference to libjpeg-turbo, so apps that depend on it never see pkg-config warnings.

Everything here needs libjpeg-turbo from Homebrew as the reference (`brew install jpeg-turbo pkg-config`).
`scripts/env.sh` finds it; run the scripts from any directory, they change to the repository root. To run `ejm`
by hand, build it with `./scripts/build.sh` (or `swift build -c release --package-path Tools` with
`PKG_CONFIG_PATH` pointing at Homebrew's jpeg-turbo, which `env.sh` sets) and call `Tools/.build/release/ejm` from
the repository root, since some commands use relative paths (`testdata/`, `results/`, `docs/images`, `README.md`).

## `ejm` subcommands

`ejm <command> [arguments]`; with no command it runs `corpus`. Numeric arguments must be integers (anything else
stops the tool). An unknown command prints "unknown command X" and exits 0 (`Tools/Sources/ejm/main.swift:124`).
Commands that check exactness exit 1 on a mismatch.

### Benchmarks

Benchmark commands print results; `bench-json` also records them. Every benchmark except `quick`, `host` and
`compile-cost` first prints the device profile in use (`device profile: ...`), waiting for its routing measurement
so it does not overlap the timing; `quick` does not read the profile, so it times the path of an app that never
does. `decode`, `encode`, `quick`, `throughput`,
`perf-small` and `perf-large` compare the outputs they time with libjpeg-turbo and print "exact" /
"byte-identical" or "DIFFERENT"; `host` and `compile-cost` run no codec work.

| command | what it does |
|---|---|
| `ejm decode [iters]` | 6720x4480 decode (q95 4:2:2, q90 4:2:0, q95 4:4:4): Metal, libjpeg-turbo on one thread, ImageIO; host time split (default 20 iterations) |
| `ejm encode [iters]` | encodes at eight export sizes against libjpeg-turbo and ImageIO, plus a cold call after 5 s of GPU idle for the small export (default 20) |
| `ejm packed-bench [rounds]` | the opt-in packed path on the three 6720x4480 synthetic cases of `ejm quick`: pack time (median of 7), the packed copy's size against the decoder's coefficient arrays, and repeat decode wall and GPU time, normal against `decode(packed:)`, interleaved in `rounds` (default 3) rounds of 15; prints the load average before and after each case |
| `ejm quick [iters]` | Metal-only medians for A/B work: the three 6720x4480 decodes (from memory and from a file) and 3840x2560 q95 / 2048x1365 q90 4:4:4 encodes (default 30). Seconds, not minutes |
| `ejm throughput [count]` | images per second for whole batches: Metal with 1 and 2 concurrent decoders or encoders, batches of 16, a GPU plus CPU hybrid, libjpeg-turbo on 1 and all cores, ImageIO (default 24; each variant runs at least 1.5 s) |

## Environment variables

`EJM_CHUNK_BITS`, `EJM_NCP` and `EJM_COLOR_SPEC` change how the decoder works (also inside `ejm`),
`EJM_FUSED_MAX_BLOCKS` sets the encoder's default entropy path, `EJM_PROFILE_CACHE=0` disables the device
profile's routing cache, `EJM_SELFCHECK_FAIL=1` forces the startup self-check to fail, `EJM_TRACE=1` prints one
line per decode and encode to stderr (`EJM_TRACE=stages` adds per-stage GPU times; every `ejm` command that
decodes or encodes then prints them), and `EJM_PROFILE` is read by `ejm perf-small`; see [API.md](API.md#environment-variables). Example, the corpus with
the generic colour kernel and small Huffman chunks:

```sh
EJM_COLOR_SPEC=0 EJM_CHUNK_BITS=1024 EJM_NCP=3 Tools/.build/release/ejm corpus | tail -1
```
